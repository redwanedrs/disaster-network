# دليل بناء شبكة الكوارث — العربية

## 1. قبل التجميع

هذا الدليل يعتمد على **مخطط الأرجل الثابت Disaster Network Rev-A**. التوزيع المرجعي للشبكات وأرجل GPIO موجود في `hardware/REV-A_PINOUT.md`، ويجب أن يطابقه المخطط واللوحة الفعلية قبل التصنيع أو إعادة العمل.

توزيع الأرجل الثابت لـ Rev-A في LoRa هو: SCK=12، MISO=13، MOSI=11، CS=10، RESET=9، DIO0=8. تم اختيار هذا التوزيع لتجنب أرجل ESP32-S3 الخاصة بالإقلاع. أرجل الـstrapping في ESP32-S3 هي GPIO0 وGPIO3 وGPIO45 وGPIO46. https://docs.espressif.com/projects/esp-idf/en/stable/esp32s3/api-reference/peripherals/gpio.html

### ملاحظات الطاقة

استخدم منطق 3.3V. تحقق من متطلبات VCC لوحدة SX1278 الخاصة بك، لأن الوحدات التجارية تختلف. إذا كان الراديو يعيد تشغيل ESP32 أو يفشل أثناء الإرسال، فراجع مصدر التغذية أولاً واستخدم أسلاك طاقة وأرضي قصيرة مع مكثفات تنعيم مناسبة.

## 2. إعداد البرنامج

ثبّت PlatformIO ثم نفّذ من مجلد المشروع:

```bash
cp firmware/common/include/disaster_secrets.h.example firmware/common/include/disaster_secrets.h
```

استبدل مفتاح AES التجريبي قبل أي استخدام حقيقي. لا ترفع `disaster_secrets.h` إلى GitHub؛ الملف مستثنى في `.gitignore`.

البناء:

```bash
pio run -e command-center
pio run -e field-sensor-node
pio run -e sos-panic-node
pio run -e messaging-node
```

يستخدم المشروع معرف لوحة PlatformIO وهو `esp32-s3-devkitc-1`. https://docs.platformio.org/en/latest/boards/espressif32/esp32-s3-devkitc-1.html

## 3. مشكلة MISO مع أرجل الإقلاع

بعض التجميعات الموجودة للمشروع قد تكون موصلة فيها إشارة LoRa MISO إلى رجل strapping في ESP32-S3. قد يؤدي ذلك إلى مشكلة أثناء وضع التحميل.

في هذه الحالة:

1. افصل التغذية.
2. افصل أو اعزل كهربائياً **سلك MISO فقط** بين LoRa وESP32.
3. ضع ESP32 في وضع التحميل المعتاد ثم ارفع البرنامج.
4. افصل USB/التغذية قبل إعادة توصيل MISO.
5. أعد توصيل MISO ثم أعد تشغيل اللوحة.

لا تغيّر مقاومات الإقلاع عشوائياً. يجب الرجوع إلى مخطط اللوحة المحددة؛ لأن حالة أرجل strapping تُقرأ أثناء إعادة الضبط لتحديد وضع الإقلاع. https://docs.espressif.com/projects/esp-hardware-design-guidelines/en/latest/esp32s3/schematic-checklist.html

تمت إضافة التعليق الخاص بهذه المشكلة داخل `firmware/common/include/disaster_config.h` وطبقة الراديو.

## 4. عقدة مركز القيادة

### التوصيل

صِل SX1278 كما هو موضح في `docs/wiring-diagrams/overview.md`.

الإصدار الأساسي من البرنامج يستخدم **شاشة Serial Monitor على USB كوسيلة عرض**، لتقليل عدد القطع المطلوبة. يمكن إضافة شاشة OLED أو TFT لاحقاً.

### رفع البرنامج

```bash
pio run -e command-center -t upload
pio device monitor -b 115200
```

المخرجات المتوقعة:

```text
=== Disaster Network / Command Center ===
LoRa ready. Listening for authenticated packets...
Command Center: listening...
```

### اختبار التشغيل الأول

1. شغّل مركز القيادة.
2. شغّل عقدة Field أو SOS أو Messaging بنفس مفتاح AES.
3. أرسل رسالة واحدة.
4. تأكد أن المركز يعرض ID المصدر والوجهة ونوع الرسالة ورقم التسلسل وبيانات الإشارة.
5. عند وصول SOS يجب ظهور رسالة تنبيه الطوارئ.

## 5. عقدة الحساس الميداني

### التوصيل

المدخل التناظري التجريبي هو GPIO15:

```text
إشارة الحساس -> GPIO15
GND         -> GND
VCC         -> مصدر التغذية المناسب للحساس
```

تم وضع هذا كمدخل عام فقط؛ يجب استبداله بسائق الحساس الحقيقي عندما يتم اعتماد قطعة الحساس النهائية.

### الرفع والاختبار

```bash
pio run -e field-sensor-node -t upload
pio device monitor -b 115200
```

ترسل العقدة رسالة `FIELD ONLINE` عند بدء التشغيل ثم تقرير ADC كل 30 ثانية.

## 6. عقدة زر SOS

### التوصيل

الزر:

```text
GPIO17 ---- زر ضغط لحظي ---- GND
```

الصفارة:

```text
GPIO18 ---- دائرة قيادة/صفارة فعالة ---- GND
```

إذا كانت الصفارة تستهلك تياراً أعلى من المسموح به على GPIO، استخدم ترانزستور أو MOSFET بدلاً من تشغيلها مباشرة من الرجل.

### الرفع والاختبار

```bash
pio run -e sos-panic-node -t upload
pio device monitor -b 115200
```

اضغط الزر مرة واحدة. يجب إرسال رسالة SOS إلى مركز القيادة وتشغيل النمط `... --- ...`.

روتين Morse يعتمد على `millis()` وحالة داخلية، ولذلك لا يستخدم `delay()` أثناء تشغيل نمط SOS.

## 7. عقدة المراسلة ولوحة 4×4

### التوصيل

```text
صف 0 -> GPIO1
صف 1 -> GPIO2
صف 2 -> GPIO16
صف 3 -> GPIO17
عمود 0 -> GPIO4
عمود 1 -> GPIO5
عمود 2 -> GPIO6
عمود 3 -> GPIO7
```

### الوظائف

في الوضع العادي:

```text
1 STATUS OK       5 TRAPPED
2 NEED WATER      6 FIRE
3 NEED MEDICAL    7 INJURED
4 EVACUATE        8 LOCATION SENT
```

اضغط `B` للدخول إلى وضع الرسائل المخصصة:

```text
2-9 = كتابة متعددة الضغط للحروف والأرقام
0   = مسافة
*   = حذف
A   = مسح
#   = إرسال
D   = إلغاء
```

للكتابة متعددة الضغط، اضغط المفتاح نفسه عدة مرات خلال 800 ms للتنقل بين الأحرف، ثم توقف وانتقل إلى المفتاح التالي.

### الرفع

```bash
pio run -e messaging-node -t upload
pio device monitor -b 115200
```

## 8. اختبار الشبكة بين العقد

ابدأ بمركز القيادة وعقدة إرسال واحدة.

1. تأكد من تطابق إعدادات LoRa بين العقد.
2. تأكد من تطابق مفتاح AES المكون من 16 بايت.
3. أرسل رسالة مسبقة.
4. نفّذ اختبار SOS.
5. غيّر المفتاح على عقدة واحدة وتأكد من رفض الحزم غير القابلة لفك التشفير في المركز.

مكتبة LoRa لا تضيف التشفير بنفسها؛ لذلك تعتمد الشبكة على طبقة التشفير الموجودة في المكتبة المشتركة للمشروع. https://github.com/sandeepmistry/arduino-LoRa#faq

## 9. قائمة ما قبل الاستخدام الميداني

- تثبيت إصدار اللوحة وPCB النهائي.
- استبدال مفتاح AES التجريبي وتحديد طريقة آمنة لتوزيع المفاتيح.
- إضافة حماية من إعادة تشغيل الحزم Replay Window وعمليات ACK/Retry.
- التحقق من قوانين استخدام 433 MHz في بلد التشغيل، بما في ذلك القدرة وعرض النطاق وDuty Cycle.
- اختبار الهوائي والتخطيط RF والعلبة.
- اختبار البطارية والشحن والـbrownout والحرارة.
- تحديد شاشة العرض الفيزيائية لمركز القيادة.
- استبدال مدخل ADC العام بدعم الحساس الحقيقي.
- تنفيذ واجهة CanSat بعد تثبيت مواصفات الكهرباء والبروتوكول.
